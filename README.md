# Syncing Blueprints to Home Assistant

This repo is the source of truth for blueprint *source*, but Home Assistant installs
are the source of truth for what is **deployed**. To push repo changes to HA:

## Pieces

- `blueprints/sync_manifest.json` — maps each repo file to its path under HA's
  `/config/blueprints/<domain>/` (e.g. `automation/climate-alert.yaml` →
  `climate-alert.yaml`, `automation/foo.yaml` → `jeeftor/foo.yaml` for files
  imported via the GitHub import flow).
- `blueprints/sync_blueprints.sh` — fetch-and-apply script run *on the HA host*;
  reads the manifest, downloads each file at a pinned commit SHA (bypasses the
  GitHub raw CDN cache), writes only changed files.
- HA side: `shell_command.sync_blueprints` (in `configuration.yaml`) resolves the
  latest master SHA via the GitHub API and pipes this script to `sh`.
  `script.sync_blueprints` wraps it with `automation.reload` + a notification.

## Usage

1. Edit/commit/push a blueprint in this repo.
2. In HA, run **Sync Blueprints from GitHub** (script.sync_blueprints) — or add
   any trigger to call it on a schedule.
3. New blueprint? Add it under `blueprints/automation/` or `blueprints/script/`,
   add a `sync_manifest.json` entry with its HA target path, push, sync.

To audit drift (live vs repo), run `shell_command.export_blueprints` on HA —
it writes `www/blueprints_export.tgz`, fetchable at `/local/blueprints_export.tgz`.
